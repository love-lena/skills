Comparison example · illustrative decision

Use one file for the reading pack

A self-contained HTML file is the simpler choice for a document that people download, keep, and open offline.

Recommendation: embed the document’s styles and diagrams. Revisit this choice if the pack grows into a frequently updated collection of pages.

What changes between the options

CriterionSingle HTML fileShared assets
Offline useOne file carries the reading experience.Needs a complete local bundle or cached assets.
SharingSend one attachment.Send a folder, archive, or hosted link.
Style updatesRegenerate each document.Update a common stylesheet for connected pages.
Repeated assetsCopied into each document.Can be reused across the collection.

The tradeoff

Embedding favors portability over centralized updates. That is a good fit for a review artifact whose content and appearance should stay together as a snapshot.

What would change the recommendation?

Choose shared assets when the main use is a connected collection, updates should propagate immediately, and offline sharing is secondary.

Scope of this comparison

This example compares packaging, not a particular hosting service or framework. File size and loading performance would need measurement against the actual documents.
