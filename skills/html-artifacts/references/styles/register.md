# Register · cobalt worksheet

The repeated record is the organizing unit. Shared column axes make comparisons cheap; exceptions receive local emphasis.

## Composition

Let the table occupy the page. Begin with records or a compact working label when that is the useful entry point. Put a conclusion or exception in a margin, an expanded row, or a nearby note keyed to the relevant values. Use the row/column hierarchy to replace stacks of repeated cards.

The approved example is wide (1600 × 900), with an annotation margin. Its proportions serve that comparison; a longer register can scroll vertically, and a narrow viewport can scroll the table locally or expose an equivalent record view.

## Visual language

Near-white paper, ink `#14233D`, cobalt `#1739C7`, selected cells `#E5ECFF`, rules `#BCC9DC`. Use system sans-serif and tabular numbers. Compact row rhythm, square edges, thin rules, and almost no shadow make alignment do the work. Restrict strong color to a meaningful shared field, selection, or exception.

## Apply it

- **KPIs:** metric/current/previous/change rows with aligned units, periods, and exception notes.
- **Design feedback:** component or screen/version rows; comments expand at their subject instead of collecting in an unrelated panel.
- **Fast forms:** in-place value entry, field-level validation, predictable keyboard traversal, and clear save state.
- **Explainers:** align actors or options against shared questions so the reader can see the invariant and the difference.

Choose this for scanning and repeated operations. Long narratives and unfamiliar multi-part questions may need a more authored path. A table of prose paragraphs loses the benefit.
